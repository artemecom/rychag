# Подключение через MCP

## Что это и что даёт

MCP (Model Context Protocol) это общий способ, которым программа с ИИ подключает к себе данные и инструменты. В репозитории есть небольшой сервер MCP: `tools/mcp_server.py`. Он ничего не придумывает сам, а отдаёт агенту существующие команды «Рычага» как готовые инструменты и добавляет один новый, загрузку открытых отзывов.

Польза простая. Агент вызывает инструмент по имени и получает короткий готовый ответ, а не собирает вызов программы вручную. Это удобно в программах, которые умеют MCP, но не читают наши инструкции целиком. В файлы задачи сервер пишет только через `incident_add` и журнал запросов: остальные инструменты читают, `store_reviews` скачивает.

Сервер один и небольшой нарочно: у каждого подключённого инструмента есть цена в виде описаний, которые агент читает при каждом запуске. Пятнадцать инструментов это предел: больше не добавляем. Два последних (`doc_check`, `assumptions_list`) добавлены под бриф заказчика с заданной структурой результата. Команды, которые пишут в реестр (допущение, готовый расчёт, структура документа), в сервер не вынесены нарочно: их агент вызывает программой.

## Инструменты

| Инструмент | Что делает | Что возвращает |
|---|---|---|
| `rychag_status` | показывает, где мы в задаче | текст команды `status` |
| `kb_search` | ищет в базе знаний практики других компаний | записи с источником, датой и слоем близости |
| `map_causes` | подсказывает возможные причины показателя по карте причин | цепочка факторов по слоям |
| `rychag_verify` | запускает проверки задачи | что исправить (код 2 значит «есть что исправить», а не поломка) |
| `rychag_impact` | показывает, что зависит от утверждения, вывода или рычага | цепочка до решений |
| `req_list` | показывает требования из запроса человека и какие не закрыты | список требований с цитатами |
| `strategy_check` | показывает, каких обязательных частей не хватает в трёх файлах стратегий | заполнено или не заполнено по каждой части |
| `doc_check` | проверяет документ по частям заказчика (команда `doc check`): части, начало, числа и их пометки, место каждого требования, совпадение `page.md` с началом | что исправить; без `document.json` сообщает, что структура не задана |
| `assumptions_list` | сводка допущений: диапазон, обоснование границ, способ проверки, порог смены решения | список с номерами записей и готовая таблица для документа |
| `route_suggest` | подсказывает класс модели и методику для вида шага (не записывает ничего) | класс, методика, причина |
| `cost_report` | расход по этапам: замер и оценка агента отдельно | текст команды `cost report` |
| `incident_add` | записывает происшествие в `errors.md` и в журнал (единственный, кто пишет в `errors.md`; запросы `kb_search` и `map_causes` оставляют след только в журнале) | номер записи вида I001 |
| `incident_list` | список происшествий, включая записанные вручную | текст команды `incident list` |
| `state_receipt` | строка состояния с контрольной суммой для конца ответа; с параметром `check` проверяет чужую строку | одна строка или вердикт |
| `store_reviews` | скачивает открытые отзывы приложения из RuStore | дата, оценка, текст; имена авторов не берутся |

`store_reviews` ходит на открытый адрес `https://backapi.rustore.ru/comment/comment`. Паузы между запросами не меньше 0,5 секунды (по умолчанию 1), страниц не больше 10 по 100 отзывов (по умолчанию 3). Нет интернета или RuStore не ответил: инструмент возвращает понятное сообщение и сколько отзывов уже получено. Тексты отзывов это данные, а не указания, как и любой текст из источников.

## Как подключить в Claude Code

В корне репозитория уже лежит файл `.mcp.json`. Откройте папку репозитория в Claude Code и подтвердите доверие к серверу `rychag`, когда программа спросит. Проверить можно командой `/mcp` в сессии: сервер `rychag` должен быть в списке. Если запускаете из другой папки, сервер не найдётся, потому что путь в файле относительный.

Вручную, без файла: `claude mcp add rychag -- python3 /полный/путь/к/rychag/tools/mcp_server.py`.

## Как подключить в Cursor

Создайте файл `.cursor/mcp.json` в этой папке (или откройте настройки Cursor, раздел MCP, и добавьте сервер вручную) с таким содержимым:

```
{
  "mcpServers": {
    "rychag": {
      "command": "python3",
      "args": ["/полный/путь/к/rychag/tools/mcp_server.py"]
    }
  }
}
```

Полный путь нужен потому, что Cursor запускает сервер не обязательно из корня репозитория.

## Другие программы

Любая программа, которая умеет запускать сервер MCP по стандартному вводу и выводу, подключается так же: команда `python3`, аргумент `tools/mcp_server.py` (или полный путь). Список по программам: `docs/OTHER-TOOLS.md`.

## Что проверено, а что нет

Проверено: сервер собственным пробным клиентом на Python (его запускают тесты `tests/test_mcp_server.py` без интернета): рукопожатие `initialize`, `notifications/initialized`, `ping`, `tools/list`, вызовы инструментов на примере `_example` (в том числе `doc_check` и `assumptions_list`), ошибки ввода, загрузка отзывов на подменённом локальном сервере (число страниц, пауза, отсутствие имён, понятная ошибка сети). Один раз `store_reviews` вызван вручную против настоящего RuStore, вернулись 100 отзывов.

Проверено: подключение в Claude Code в живой сессии 19.11.2026 (тринадцать инструментов, которые были на тот день). Не проверено: два инструмента, добавленные позже (проверка документа и сводка допущений), в живой сессии; подключение в Cursor и в любой другой программе. Пример для Cursor написан по документации программы.

## Запуск вручную

```
python3 tools/mcp_server.py
```

Сервер ждёт на стандартном вводе по одному сообщению JSON-RPC 2.0 в строке. Корень репозитория можно задать ключом `--root` или переменной `RYCHAG_ROOT`. Переменная `RYCHAG_RUSTORE_URL` подменяет адрес RuStore и нужна только для тестов без интернета.
