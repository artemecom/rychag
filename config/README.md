# Настройки «Рычага»

Файлы JSON не умеют комментариев, поэтому пояснения здесь. Любой файл можно править руками, проверка: `python3 tools/rychag.py doctor`.

## sources.json: источники (слой 1)

- `allowlist`: список разрешённых сайтов, например `["rosstat.gov.ru", "cbr.ru"]`. Поддомены разрешены вместе с основным сайтом. Пустой список значит «можно любые сайты».
- `max_sources_per_question`: потолок источников на один подвопрос (по умолчанию 10). Нужен, чтобы агент не утонул в чтении. Расчёты в потолок не входят.
- `freshness_days`: насколько старым может быть источник, в днях (по умолчанию 730, то есть два года). Источник без даты публикации не отклоняется, но даёт предупреждение.
- `kb_freshness_days`: насколько старой может быть запись базы знаний (по умолчанию 1095, три года). Старше: `kb stale` и `kb list --stale` их покажут.

## style.json: итоговая страница (слой 5)

- `max_page_lines`: сколько непустых строк можно на странице (сейчас 32). Тот же порог действует для начала документа по частям заказчика (до первой части); длина самого документа не ограничена.
- `abbreviations`: список сокращений, которые нельзя оставлять на странице, в виде `{"abbr": "п.п.", "write": "процентных пункта"}`. Проверка слоя 5 находит их как замечания и подсказывает, чем заменить. Регистр и число пробелов не важны. Пустой список отключает проверку.
- `banned_phrases`: пустые обороты, которые проверка ищет в `page.md` и в `document.md` (регистр и «ё» не важны). Список можно пополнять: сюда стоит добавлять обороты, которые вы сами вычёркиваете при правке.

## routing.json: выбор модели

Простая таблица `table`: для какого вида шага какую модель можно брать. `дешёвая` для механической работы, результат которой проверяет скрипт, `сильная` для суждений. У строки есть поля `method` (какую методику перечитать при повторной неудаче) и `stages` (к каким этапам относится строка). Когда `gate` или `verify` второй раз подряд не проходят с теми же замечаниями, программа по этим полям называет класс модели выше и методику (`route suggest --step "..."` показывает то же вручную). Агент читает таблицу перед тем, как поручить шаг помощнику. Конкретные названия моделей сюда не вписываются: их выбирает тот, кто запускает агента.

## process.json: остановки для руководителя

`stops_need_answer` (сейчас `true`): на этапах 1, 2, 5 и 7 агент обязан показать результат руководителю и остановиться. Перейти дальше можно только командой `stage next --answer "<слова руководителя>"`: ответ сохраняется в состоянии задачи и виден в `status`. Пока руководитель не ответил на остановках 1 и 2, программа не принимает расчёты, допущения и закрытие требований. `false` возвращает прежний порядок: остановки остаются указанием в инструкции, программа их не проверяет.

## synonyms.json: синонимы для поиска по базе знаний

`groups`: списки взаимозаменяемых слов (отток, уход, потеря). Поиск `kb search` расширяет каждое слово запроса словами его группы. Стартовый набор из 30 групп по телекому и продукту, пополняйте его своими словами. Слова пишутся в нижнем регистре.

## Слои близости доказательств

Каждый источник и запись базы знаний несёт слой от 1 до 5: 1 данные самого продукта; 2 данные компании и её других сервисов; 3 отрасль в той же стране; 4 отрасль в мире; 5 смежные отрасли (банки, подписки, приложения других сфер). Источники из `materials/` по умолчанию слоя 1, страницы из сети обязаны указать `--layer`, записи базы знаний слоя 2-5. Находка или причина о продукте требует факта слоя 1, рекомендация или вариант требует факта слоя 1 или 2. Число из слоёв 3-5 на итоговой странице допустимо только в строке со словом «ориентир».
