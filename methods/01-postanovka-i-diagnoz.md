# 01. Постановка задачи и диагноз вопроса

## Когда применять

Этапы 1 и 2. Любой новый вопрос руководителя, пока не ясно, какой показатель, какой срез (часть пользователей по одному признаку) и какое решение он примет по итогам. Здесь же выбирается маршрут по `methods/INDEX.md`.

**Когда не применять:** постановка закрыта (`rychag status` показывает этап 3 и дальше); вопрос сменился по сути: это новая задача `rychag new`, а не правка старой.

## Что нужно на входе

- Вопрос руководителя дословно (он уже в `brief.md` после `rychag new`).
- Для просадки: какой показатель, с какой даты, насколько упал; что менялось в продукте, ценах и рекламе на эту дату.
- Для нового сервиса: что это за сервис, для кого задуман, что решает руководитель (запускать ли, кому продавать, как говорить).
- Показатель не назван числом: попроси одно «выгрузка показателя по неделям за последние 6 месяцев и дата, с которой вы видите падение». Не угадывай, жди ответа.

## Шаги

1. Определи тип вопроса по маршрутам в `methods/INDEX.md`: просадка, конверсия, запуск, сообщение аудитории, судьба направления, стратегия по брифу заказчика.
   Заказчик прислал бриф и сам назвал, из чего состоит результат: положи бриф в `materials/`, сохрани источником (`rychag source add --file ...`), выпиши каждое его требование и каждое предупреждение об ошибке (`rychag req add --source S001 --text "..." --quote "<дословно>"`) и задай части результата: `rychag doc init --title "..." --opening "<что назвать в начале>" --part "<часть>"`. Дальше по разделу «Документ по частям заказчика» в `methods/INDEX.md`. Поля `brief.md` про просадку заполни словами «не относится: стратегия по брифу».
2. Перепиши вопрос в решение: «руководитель выбирает между X и Y к такой-то дате». Решения не видно: это первый вопрос человеку.
3. Каждый вопрос человеку проходит фильтр «изменит ли ответ мой следующий шаг». Не проходит: не задавай. Не больше трёх сразу:
   `rychag question add --text "Что менялось в продукте, тарифах и рекламе с 1 июля?" --if-yes "проверяю связь изменения с просадкой" --if-no "ищу причину в срезах данных"`
   При просадке этот вопрос обязателен.
4. Ответ закрывай и переноси в `brief.md`: `rychag question close 1 --answer "<ответ дословно>"`.
5. Заполни все поля `brief.md`. Для вопроса о запуске поля про просадку заполни словами «не относится: вопрос о запуске». Пометок `<<заполнить>>` не оставляй.
6. Остановка 1: покажи постановку в пяти строках, жди «да». Затем `rychag stage next`.
7. Этап 2. Запиши 5-10 критериев «что значит готово», каждый отмечается «да» или «нет»:
   `rychag done add --text "Названа причина просадки с числами из реестра"`, бюджет `rychag done budget --usd 5`.
8. План исследования в `analysis/plan.md`: 3-6 подвопросов. У каждого: какой ответ поменял бы решение, где искать (файл руководителя, сайт из разрешённого списка), сколько источников (не больше 10, лучше 5 прочитанных целиком).
9. Остановка 2: покажи критерии, план и бюджет. После «да»: `rychag stage next`.

## Шаблон результата

`brief.md`: вопрос; решение руководителя; показатель с числом (или «не относится»); дата начала; что менялось на эту дату; что решает руководитель.
`analysis/plan.md`, строка на подвопрос:
`| Подвопрос | Какой ответ меняет решение | Где ищем | Сколько источников |`
`done.json`: критерии D1...Dn и бюджет, только через `rychag done add`, `rychag done budget` и `rychag done mark`, руками не править.

## Чем проверяется

`rychag stage next` на этапе 1 не пустит дальше с пометками `<<заполнить>>` в `brief.md`; `rychag question add` не откроет четвёртый вопрос; на этапе 2 нужны критерии и бюджет. Нужен ли вопрос и проверяем ли критерий, программа не проверяет.

Вопросы себе: какое решение примет человек по итогам; какой мой вопрос можно не задавать; что я сделаю по-разному при «да» и при «нет».

## Частые ошибки

- Анкета из десяти вопросов вместо трёх, от которых зависит следующий шаг.
- Не спросили, что менялось на дату начала просадки, и причину ищут вслепую.
- Критерий нельзя проверить: «стратегия понятна» вместо «у каждого рычага есть порог провала».
- «Почему падает» оставлено без числа и даты: неясно, что упало.
- План из тем («рынок», «конкуренты») без ответа, который меняет решение.

## Основание

Вопрос про изменения на дату: у Amplitude главные провалы диагностики от нехватки контекста о релизах (<https://amplitude.com/blog/diagnostic-analytics-trustworthy>). Договор «готово» до работы: Anthropic (<https://anthropic.com/engineering/harness-design-long-running-apps>). Фильтр вопросов и план по ответам, меняющим решение: наша сборка.
